# LAN and HTTPS considerations

Connect devices to the same trusted Wi-Fi. On Windows CMD, use `ipconfig` to find the host's IPv4 address. The server would need to bind to a LAN interface (e.g. `--host 0.0.0.0`) and a restrictive Windows Firewall rule; clients then use `http://HOST_IPV4:8000/`. This is **not** appropriate for real medical data on unencrypted HTTP. Phone browsers generally require HTTPS secure contexts for camera access, so QR upload may work when live camera scanning does not. For a real cross-device demonstration, use a trusted locally configured HTTPS reverse proxy with a certificate trusted by each client and restricted LAN access. Configure `CORS_ORIGINS` explicitly, avoid exposing the development server to the public internet, and protect database files, uploads, and secrets. These steps were not exercised in this patch.
